# Replay, capture filtering, WebSocket and HTTP/2

User-authorized implementation in the existing SwiftUI/SwiftNIO application.

1. Replay and compose: validate URL, method and headers; normalize Host/Content-Length and hop-by-hop headers; preserve binary bodies; prohibit replaying truncated requests and CONNECT/upgrade requests. Execute explicitly from the app, retain as a new transaction linked to the original, allow cancellation and inspect errors. Reuse upstream routing and TLS validation. Show an editor with URL/method/headers/text-or-file body.
2. Capture rules: persistent enabled include/exclude rules by hostname/path/method/device IP. Excludes win; empty include means all. Forwarding is unaffected. Focus uses separate persistent location rules and filters only the displayed list; right-click adds focused hosts. Filter before the 1,000 row page limit so matching traffic remains accessible.
3. WebSocket: forward HTTP/1.1 ws/wss upgrade and bidirectional frames; keep handshake headers, connection source, timestamps, directions, opcode and bounded payloads. Decode fragmented text/binary messages and permessage-deflate only if supported; negotiate without that extension otherwise. Persist messages incrementally in a separate table and display live messages with decoded/hex preview. Propagate closure, mask handling, ping/pong and backpressure, respect recording policy and access revocation. RFC8441 over HTTP/2 is outside this stage.
4. HTTP/2: ALPN h2/http1.1 on intercepted TLS, NIOHTTP2 stream multiplexer plus HTTP2-to-HTTP1 adapter into the existing handler; preserve physical client channel for admission/cancellation/source. Upstream AsyncHTTPClient automatic HTTP/2 with HTTP/1 fallback. Capture actual downstream/upstream versions separately. TLS and mobile approval remain mandatory. Test multiple concurrent streams and mixed protocol legs.
5. Verify with local HTTP/HTTPS/WS/WSS/H2 fixtures, legacy session/HAR compatibility, UI smoke tests and universal packaging. No real recorded POST is replayed during testing; use synthetic requests.
